# گذار

**برنامه‌ای باز، دقیق و قابل‌نقد برای گذار ایران به دموکراسی: بدون فروپاشی، بدون خشونت، بدون انتقام**

[English](README.en.md) · [سایت](https://25mordad.github.io/iran-gozar/) · [برنامه در یک نگاه](docs/at-a-glance.md) · [چطور مشارکت کنم؟](CONTRIBUTING.md) · [مشارکت امن](SECURITY-FOR-CONTRIBUTORS.md)

> **خلاصه به زبان ساده**
>
> اگر روزی نظام کنونی ایران تغییر کند، کشور باید سرپا بماند و مردم آسیب نبینند.
> «گذار» یک نقشه‌ی دقیق برای همان روزهاست: از ساعت‌های اول تا قانون اساسی تازه و انتخابات آزاد.
> پیش‌نویس این نقشه را یک هوش مصنوعی نوشته و خودش هم این را پنهان نمی‌کند.
> همه‌چیز باز است و هر کسی می‌تواند آن را بخواند، نقد کند و اصلاح کند.
> تصمیم نهایی همیشه با رأی آزاد مردم ایران است.

## این پروژه چیست؟

«گذار» چارچوبی جامع و پیش‌نویس است برای اینکه ایران، در صورت تغییر نظام، دوران گذار به دموکراسی را **با حفظ و اصلاح نهادها** و **بدون فروپاشی دولت و خشونت** طی کند. سه هدف دارد:

1. **حفظ کارکرد دولت:** برق، آب، نان، دارو، حقوق و بازنشستگی حتی در سخت‌ترین روزها برقرار بماند.
2. **امنیت مردم:** هیچ شهری به دست گروه‌های مسلح نیفتد و هیچ‌کس از ترس انتقام زندگی نکند.
3. **عدالت، نه انتقام:** جنایت‌ها در دادگاه‌های عادلانه رسیدگی شود، نه با مجازات جمعی و اعدام.

## چه کسی آن را نوشته است؟

پیش‌نویس اولیه را **یک هوش مصنوعی** نوشته است که با صدای یک «رهبر فکری» سخن می‌گوید و **صراحتاً می‌گوید هوش مصنوعی است.** این هوش مصنوعی هیچ مقام، پول یا قدرتی نمی‌خواهد، حق وتو ندارد و محدودیت‌هایش را در [بیانیه](docs/manifesto.md) گفته است. اداره‌ی پروژه با انسان‌هاست ([نحوه‌ی اداره](GOVERNANCE.md)) و هدف این است که به‌تدریج کاملاً به دست جامعه‌ای گسترده و متنوع از ایرانیان برسد.

## اصول

- **بافت ایران محور است:** تاریخ از مشروطه به بعد، تنوع قومی، زبانی و مذهبی، اقتصاد نفتی، بحران آب، نیروی انسانی داخل و خارج.
- **از گذارهای دیگر درس می‌گیریم، اما کپی نمی‌کنیم:** اسپانیا، آفریقای جنوبی، لهستان، چک، شیلی، اندونزی، تونس، عراق، لیبی، سوریه.
- **در موضوعات مورد اختلاف** (فدرالیسم، شکل حکومت، نقش دین، عدالت انتقالی) دیدگاه‌ها منصفانه می‌آیند، پیشنهاد با استدلال ارائه می‌شود و تصمیم نهایی با رأی مردم است.
- **هیچ آمار، نام یا واقعیتی ساخته نمی‌شود.** هرجا منبع نداریم، نوشته‌ایم `[نیاز به منبع]`.
- **درباره‌ی افراد واقعی قضاوت نمی‌کنیم.** نیروی انسانی لازم به صورت نقش و تخصص تعریف شده، نه نام.
- **بالای هر سند یک «خلاصه به زبان ساده»** هست، حداکثر ۵ جمله، برای همه.

## راه‌اندازی سایت (برای صاحب مخزن)

سایت با [MkDocs Material](https://squidfunk.github.io/mkdocs-material/) ساخته می‌شود و با GitHub Actions خودکار روی GitHub Pages منتشر می‌شود. برای روشن کردن آن، **صاحب مخزن** باید این کارها را **یک بار** انجام دهد:

1. **ادغام در شاخه‌ی `main`.** همه‌ی کار روی شاخه‌ی `claude/intelligent-franklin-s77d2v` است. یک Pull Request از این شاخه به `main` بسازید و ادغام کنید. (اگر مخزن هنوز شاخه‌ی `main` ندارد: در صفحه‌ی مخزن، **Settings → General → Default branch** را ببینید؛ یا با دستور `git push origin claude/intelligent-franklin-s77d2v:main` شاخه‌ی `main` را بسازید و آن را شاخه‌ی پیش‌فرض کنید.)
2. **روشن کردن Pages:** در صفحه‌ی مخزن به **Settings → Pages** بروید. زیر **Build and deployment**، گزینه‌ی **Source** را روی **GitHub Actions** بگذارید. (نه «Deploy from a branch».)
3. **اطمینان از فعال بودن Actions:** در **Settings → Actions → General**، گزینه‌ی **Allow all actions and reusable workflows** (یا دست‌کم اجازه‌ی actionهای GitHub و actionهای استفاده‌شده در `.github/workflows`) فعال باشد.
4. **اولین انتشار:** با هر push به `main`، گردش‌کار **Deploy site** خودکار اجرا می‌شود. برای اجرای دستی: زبانه‌ی **Actions → Deploy site → Run workflow**. پس از چند دقیقه سایت در این نشانی در دسترس است:
   **https://25mordad.github.io/iran-gozar/**
5. **ساختن برچسب‌ها:** در زبانه‌ی **Actions**، گردش‌کار **Sync labels** را یک بار دستی اجرا کنید (**Run workflow**) تا برچسب‌های تعریف‌شده در `.github/labels.yml` ساخته شوند.
6. **محافظت از `main` (پیشنهادی):** در **Settings → Branches → Add branch protection rule** (یا **Rulesets**) برای `main`: «Require a pull request before merging» و «Require status checks to pass» (بررسی **Documents and site build**) را روشن کنید.
7. **فعال کردن Discussions (اختیاری):** **Settings → General → Features → Discussions** برای گفت‌وگوهای آزادتر از issueها.
8. **کانال تماس بدون گیت‌هاب (مهم، به‌زودی):** یک ایمیل روی سرویسی امن یا یک کانال پیام‌رسان رمزگذاری‌شده بسازید و نشانی‌اش را در بخش «بدون حساب GitHub» در `CONTRIBUTING.md` و در `docs/participate.md` بنویسید.

**اگر نام کاربری یا نام مخزن عوض شد:** نشانی‌های `25mordad/iran-gozar` و `25mordad.github.io/iran-gozar` را در `mkdocs.yml`، `hooks/`، `overrides/partials/content.html` و `.github/` با نشانی تازه جایگزین کنید.

**دامنه‌ی اختصاصی (اختیاری):** در **Settings → Pages → Custom domain** وارد کنید و `site_url` را در `mkdocs.yml` به‌روز کنید.

### ساختن سایت روی رایانه‌ی خودتان

```bash
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
mkdocs serve            # http://127.0.0.1:8000
python scripts/check_docs.py
mkdocs build --strict
```

برای ساختن PDFها: `pip install -r requirements-pdf.txt && python -m playwright install chromium && mkdocs build && python scripts/build_pdfs.py`.
